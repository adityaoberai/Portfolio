# Design Guidance

The design should feel like a thoughtful personal home rather than a traditional developer portfolio or SaaS landing page.

The website should communicate confidence through restraint. Typography, spacing, and content should do most of the work, rather than relying on elaborate visual effects.

## Design Principles

Every design decision should reinforce these principles:

- Editorial over corporate
- Personal over polished
- Calm over loud
- Timeless over trendy
- Thoughtful over flashy
- Fast over feature-rich

The experience should feel closer to reading a beautifully designed magazine profile than browsing a developer portfolio.

---

## Visual References

The visual language should take inspiration from products and publications known for strong editorial design and excellent typography.

Primary references:

- Stripe Press
- Linear
- Read.cv
- Monocle
- The Browser Company
- Vercel Editorial
- Pitch
- Notion's marketing site

These references share:

- Exceptional typography
- Generous whitespace
- Clear hierarchy
- Restrained color palettes
- Beautiful photography
- Subtle motion
- Long-form readability

The goal is inspiration, not imitation.

---

## Overall Visual Identity

The site should feel:

- Warm
- Minimal
- Modern
- Editorial
- Intelligent
- Curious
- Approachable

Visitors should leave with the impression that they are exploring the personal website of someone who enjoys building, writing, teaching, and learning—not someone trying to impress them with visual effects.

---

## Layout System

Use a spacious editorial layout.

Guidelines:

- Wide but readable content widths
- Consistent spacing scale
- Strong vertical rhythm
- Plenty of breathing room between sections
- Cards used sparingly and intentionally
- Avoid overly dense interfaces

Each page should feel visually calm.

---

## Typography

Typography is the primary design element.

Suggested hierarchy:

- Display font for large headings (serif or humanist)
- Clean sans-serif for body copy
- Monospace reserved for technical metadata

Typography should create personality before color or imagery does.

Headings should feel confident but not oversized.

Body text should be comfortable for extended reading.

---

## Color Palette

The palette should remain understated.

Suggested foundation:

Background

- Soft off-white

Primary text

- Charcoal

Borders

- Warm gray

Accent

- One muted brand color

Optional secondary accent

- Used only for interaction states

The palette should support the content, not compete with it.

Avoid:

- Neon colors
- Heavy gradients
- Excessive shadows
- Glassmorphism
- Bright "AI" aesthetics

---

## Imagery

Photography should be intentional rather than decorative.

Possible usage:

- Portrait on About page
- Community photographs
- Speaking photographs
- Project screenshots
- Occasional lifestyle photography

The website should not become a gallery.

Instead, it should invite visitors to explore the complete photography portfolio on Pexels.

---

## Iconography

Use simple outline icons where appropriate.

Avoid:

- Decorative illustrations
- Generic programming icons
- Cartoon-style graphics

Icons should support navigation, never dominate it.

---

## Motion

Motion should be subtle and purposeful.

Recommended:

- Hover transitions
- Button interactions
- Card elevation
- Small page fades
- Smooth scrolling

Avoid:

- Scroll-jacking
- Overly complex page transitions
- Long loading animations
- Motion that delays interaction

The site should feel responsive and lightweight.

---

## Homepage Experience

The homepage should not resemble a résumé.

Instead, it should follow this rhythm:

1. Quiet hero
2. Personal introduction
3. Professional proof
4. Selected work
5. Community and speaking
6. External destinations
7. Contact

The first screen should immediately communicate personality, not credentials.

---

## Content Style

Copy throughout the website should be:

- Human
- Direct
- Specific
- Curious
- Reflective
- Honest

Avoid:

- Marketing clichés
- Buzzwords
- Generic "passionate developer" language
- Long mission statements

Whenever possible, demonstrate experience through stories and examples rather than adjectives.

---

## External Destinations

External links should feel like curated destinations.

Instead of simple navigation items, they should invite exploration.

Examples:

- Read my writing on Substack
- Explore my photography on Pexels
- Browse my projects on GitHub
- Download my résumé

The website should act as the central hub connecting these platforms.

---

## Mobile Experience

The mobile experience should receive equal design attention.

Requirements:

- Comfortable reading widths
- Large touch targets
- Simple navigation
- Minimal scrolling friction
- Responsive typography
- Optimized images

No feature should exist only on desktop.

---

## Accessibility

The website should meet modern accessibility expectations.

Requirements:

- Semantic HTML
- Keyboard navigation
- Visible focus states
- Proper heading hierarchy
- Sufficient color contrast
- Meaningful alt text
- Reduced-motion support

---

## Success Criteria

When someone leaves the website, they should think:

> "Aditya works on interesting problems, communicates them clearly, and builds meaningful communities."

Not:

> "That's a nice portfolio."

The website should make visitors want to follow Aditya's work—not simply skim his experience.
